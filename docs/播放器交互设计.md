# 播放器交互设计

本文记录现行桌面播放器的交互决策。早期方案见 [产品设计与技术架构](产品设计与技术架构.md)；实际实现以当前代码为准。

## 剧场键盘操作与焦点

剧场模式采用**播放快捷键优先**的设计：观看时，键盘操作应持续控制当前播放，而不会因为刚点击过选集、播放按钮、音量滑块或全屏按钮，就把后续按键交给这些控件。用户可以连续使用空格或 K 播放/暂停、上下方向键或 Page Up/Down 切集、左右方向键快退/快进，以及 F 切换全屏。

为实现这一行为，剧场中的按钮、范围滑块和选择控件获得焦点时，播放器会将焦点移回播放区域；指针操作后的焦点也会被整理。这是有意的交互选择，并非漏掉了 Tab 焦点管理。其代价是：**剧场内不能依赖 Tab 逐项聚焦并操作这些控件**。播放、切集、跳转和全屏等操作通过播放器快捷键提供，其他设置仍需通过界面操作。

文本输入框、文本区域和可编辑内容是例外：输入文字时不触发播放器快捷键，避免干扰搜索等输入。选择框获得焦点时也不执行全局快捷键。Escape 会优先处理已打开的菜单或弹窗；全屏时先退出全屏，并有短暂保护，避免同一次操作继续退出剧场。

## 维护与评审约束

- 不要仅因为剧场内控件不能通过 Tab 保持焦点，就将当前行为判定为缺陷或直接移除焦点处理。这是经过确认的播放优先设计。
- 修改快捷键或焦点逻辑时，应验证：点击选集、滑块、播放及全屏控件后，播放快捷键仍按预期控制视频；文本输入和弹窗 Escape 行为不受影响。
- 如果未来需要增加完整的逐控件键盘导航或其他无障碍操作，应先明确与播放快捷键的冲突和交互模式，再调整设计与测试，不能静默改变当前行为。
